🔄 Customer Type & MSXpert Access - Functionality Status

⚠️ Current Status: Partially Working

The customer type and MSXpert access changes will show in the UI and log the changes, but won't persist to the database until backend API endpoints are implemented.

🔍 What Happens When You Make Changes

✅ What Works (UI Level):

  • Edit modal opens and closes
  • Form fields update correctly
  • Success toast messages appear
  • Changes logged to browser console
  • Data refresh is triggered
  • Loading states work properly

❌ What Doesn't Work (Database Level):

  • Changes not saved to database
  • Changes lost after page refresh
  • No API calls to backend
  • Customer type not persisted
  • MSXpert access not persisted

🧪 Test the Current Functionality

Step 1: Go to Customer Types
Admin Dashboard → Permissions → Customer Types → User Management
Step 2: Click "Edit" on any user
Step 3: Change customer type (e.g., SPRINGER → WILEY)
Step 4: Toggle MSXpert access
Step 5: Click "Save Changes"
Step 6: ✅ You'll see:
  • Success toast: "User Updated (UI Only)"
  • Console log with the changes
  • Modal closes
  • Data refresh happens
Step 7: ❌ But if you refresh the page:
  • Changes are lost
  • User reverts to original customer type
  • MSXpert access reverts to original state

🔧 What's Needed for Full Functionality

1. Backend API Endpoints:
PUT /api/admin/users/{userId}/customer-type Body: { customerType: "SPRINGER" | "WILEY" | "F1000" | "DMP" } PUT /api/admin/users/{userId}/msxpert-access Body: { msxpertAccess: boolean } PUT /api/admin/users/{userId}/profile Body: { name: string, role: string }
2. Database Schema Updates:
ALTER TABLE users ADD COLUMN customer_type VARCHAR(20); ALTER TABLE users ADD COLUMN msxpert_access BOOLEAN DEFAULT FALSE;
3. Frontend API Integration:
